# RLX

A one-thumb arcade for an Android phone: a hub of small endless games to pick up and put down. Relaxed engagement, no thinking required. It exists to replace doom scrolling. The games are Bricks, Catch and Putt.

The plan is `docs/PLAN.md`; the rows are in `docs/BACKLOG.md`; each session is logged in `docs/CHANGELOG.md`. The look follows `docs/style-reference.jpg` (Catch: `docs/style-reference-catch.jpg`; Putt: `docs/style-reference-putt.jpg`).

## Hard rules

- Android only: Chrome now, an APK WebView later. No iOS or Safari work.
- Portrait, one thumb, one input: a horizontal drag.
- No fail state: no lives, game over, timers, streaks, daily goals, notifications, leaderboards, accounts, ads or network calls.
- No sound. Haptics only, with one on/off setting.
- Instant in, instant out: lifting the thumb pauses, closing saves, reopening resumes.
- Vanilla HTML, CSS and JS, ES modules, no build step, no dependencies, no CDN, no web fonts. Static files on GitHub Pages.
- Text never wraps or overflows its box: its size is fitted to the box.

## Layout

- `index.html`: the hub.
- `shared/`: `tokens.js` (colours, mirrored in `theme.css`; the B4 contrast pass changed some PLAN §3 values, listed in docs/CHANGELOG.md), `font.js` (the pixel font), `pixel.js` (canvas, integer scaling, stepped-corner shapes, dither, scene, page hygiene, navigation), `haptics.js`, `store.js` (localStorage, versioned keys), `settings.js`, `session.js` (the shared session clock and scene phase of the sunset exit ramp, PLAN §2b; its `SESSION` block holds the ramp, slowdown and reset-gap lengths; saved under `rlx.v1.session`).
- `games/bricks/`: Bricks. `index.html` loads `bricks.js` (drawing, the thumb, pause and save, haptics; its tuning block `CONFIG` sits at the top), which runs `physics.js` (the fixed 120 Hz simulation with swept collisions, the endless refill and the pace; no DOM, so it also runs in Node; the session clock is passed in). The game state, including the pace, is saved under `rlx.v2.bricks` and the all-time score under `rlx.v1.bricks-score`.
- `games/catch/`: Catch. `index.html` loads `catch.js` (drawing, the thumb, pause and save, haptics; its tuning block `CONFIG` sits at the top), which runs `sim.js` (the fixed 120 Hz simulation: falling things, the boat, the nasty ones and the fish, the pace, the counts, the spawn timers; the input rules for taps, the 400 ms pause grace and the resume as a small state machine; the sprite masks; no DOM, no imports, so it also runs in Node; the session clock is passed in). The game state, including the pace, is saved under `rlx.v1.catch` and the counts (caught, nasties eaten) under `rlx.v1.catch-count`. Bricks keeps its own input code and its immediate pause.
- `games/putt/`: Putt, built to the hard rules of plan update 2 (PLAN §2): no text, number, button or HUD, no back control (the Android back gesture goes home), touches that begin within 24 CSS px of the left or right edge ignored, nothing written to storage, a fresh level on every opening, haptics whenever `navigator.vibrate` exists (the hub's haptics setting is not read). `index.html` loads `putt.js` (drawing, the pull-back gesture, haptics with the shared 40 ms limit, the level queue; its play values `CONFIG` sit at the top). `sim.js` is the fixed 120 Hz simulation (swept collisions in sub-steps of at most 1 px, constant deceleration, sand, water, the hole, the aim guide; no DOM, no imports). `gen.js` is the level generator and its solver (no DOM; its values `GEN`, with the PLAN §6c table, sit at the top): a seed, a difficulty and the screen height always give the same level; `putt.js` runs `gen.js` as a module Web Worker to build the next level while one is played (in small slices on the page if a worker cannot start). Putt reads the shared session clock and advances it in memory only; it never saves it.
- `manifest.webmanifest`, `sw.js`, `icons/`.
- `tools/`, `tests/`: helper scripts. Nothing in them is needed to run the app.

All paths are relative, so the site works at a domain root or under a project subpath such as `/4rk4d3/`.

## Run locally

Serve the repo root with any static server and open it in Chrome:

    python3 -m http.server 8000
    # then open http://localhost:8000/

Use `localhost` (a secure context) so the service worker registers. Use Chrome DevTools device mode at 360 to 412 px wide to see the phone layout.

## Deploy

GitHub Pages serves the static files straight from the `main` branch, repo root. There is no build and no workflow.

1. Once: in the repo on GitHub, Settings, Pages, Source "Deploy from a branch", branch `main`, folder `/ (root)`. The site is then at `https://apcanario.github.io/4rk4d3/`. `.nojekyll` tells Pages to serve the files as they are.
2. Every deploy that changes a shipped file: run `tools/bump-sw-version.sh` (it bumps `VERSION` in `sw.js`), commit, push to `main`. If you added a shipped file, add it to `FILES` in `sw.js` too.

How updates reach the phone: `sw.js` serves every file cache-first from a cache named after `VERSION`, so the app opens offline. On each launch Chrome rechecks `sw.js` (registered with `updateViaCache: 'none'`). A changed `VERSION` installs the new worker, which caches the new files under the new name, takes over and deletes the old cache. The launch after that runs the new version.

Install: open the Pages URL in Chrome for Android, then menu, Add to home screen (or Install app). It opens standalone, in portrait.
