# RLX

A one-thumb arcade for an Android phone: a hub of small endless games to pick up and put down. Relaxed engagement, no thinking required. It exists to replace doom scrolling. The games are Bricks, Catch, Putt, Stack and Glide.

The plan is `docs/PLAN.md`; the rows are in `docs/BACKLOG.md`; each session is logged in `docs/CHANGELOG.md`. The look follows `docs/style-reference.jpg` (Catch: `docs/style-reference-catch.jpg`; Putt: `docs/style-reference-putt-open.jpg` since row U2, before it `docs/style-reference-putt.jpg`).

## Hard rules

The full list is PLAN §2.

- Android only: Chrome on the Pages URL, and the same files bundled in the Android app for Google Play (`android-app/`, PLAN §6f). No iOS or Safari work.
- Portrait, one thumb. Each game has its own gesture and its own pause.
- Full screen (the manifest's display is `fullscreen`). No game shows a title, a number, a button or any other HUD.
- Going home is the Android back gesture; there is no on-screen back control. Every game ignores a touch that begins within 24 CSS px of the left or right edge, so an edge swipe never moves anything in the game.
- No points of any kind, on screen or stored. No saved game state: nothing is written to storage, and opening a game from the hub always starts it fresh.
- No fail state: no lives, game over, timers, streaks, daily goals, notifications, leaderboards, accounts, ads or network calls.
- No sound. Haptics are always on. No settings anywhere: the hub is the five game cards and nothing else.
- Vanilla HTML, CSS and JS, ES modules, no build step, no dependencies, no CDN, no web fonts. Static files on GitHub Pages.
- No text anywhere, the hub included: no wordmark, no labels.

## Layout

- `index.html`: the hub: five framed cards in a grid of 2 columns by 3 rows (Bricks, Catch / Putt, Stack / Glide, the sixth cell left open), each a small window onto its game, low on the screen in the thumb's reach, sitting on the sea, with the sunset sky, the sun, clouds and (at dusk) stars above them; no text, nothing else (PLAN §5a). A tap on a card opens the game full screen in a frame over the hub (made on the card's touch, so the tap also counts as the game page's own and it may vibrate at once; shown when the touch lifts on the card, with one history entry; a touch that begins within 24 CSS px of a side edge opens nothing). The Android back gesture (history back) removes the frame and shows the hub. The page itself never leaves the hub, which is how the one session clock stays in memory across games. Every opening is a fresh game.
- `hub/cards.js`: the hub's card grid: the layout (sized from the screen, the safe area and the side band; cards at most 1.3 times as tall as wide; where three rows of that size do not fit, the sky gives way first, then the cards shrink; the horizon 8 px above the grid) and the hub's scene options (`hubScene`: the raised horizon, the sun sized to the sky, clouds, stars), each card's parts (its window's scene colours and its pieces, the Catch sprites taken from `games/catch/sim.js`, Glide's masks and colours from `games/glide/sim.js`; the Putt card is the open course of row U2) and their drawing. No DOM; the checks read its parts to measure contrast.
- `shared/`: `tokens.js` (colours, mirrored in `theme.css`, in two sets: light, and dark when the phone is in dark mode (row D1, PLAN §6g; no toggle, nothing stored; a switch redraws the open page on its next frame); the B4 contrast pass changed some PLAN §3 values, listed in docs/CHANGELOG.md), `pixel.js` (canvas, integer scaling, stepped-corner shapes, dither, scene, page hygiene; the shared input values `INPUT`: the thumb travel, 28 percent of the screen width end to end, and the 24 CSS px side edge that is ignored; and `clearStored()`, which removes any `rlx.*` key an earlier build left in localStorage or sessionStorage, at every start), `haptics.js` (the shared `tick()`: always on, at most one vibrate call per 40 ms; `send()` goes to the Android app's native plugin `RlxHaptics` when there is one, else `navigator.vibrate`), `native.js` (inside the Android app: `inApp()` and the native haptics plugin, the hub's first, the page's own second), `session.js` (the one session clock and the scene phase of the sunset exit ramp, PLAN §2b, in memory only: the hub holds it and the games it opens use the hub's; it resets when the app starts and when the page has been hidden for 5 minutes or more; its `SESSION` block holds the ramp, slowdown and reset-gap lengths). A game page opened on its own (by its URL) works too, with a clock of its own.
- `games/bricks/`: Bricks. `index.html` loads `bricks.js` (drawing, the thumb, pause, haptics; its tuning block `CONFIG` sits at the top), which runs `physics.js` (the fixed 120 Hz simulation with swept collisions, the endless refill and the pace; no DOM, so it also runs in Node; the session clock is passed in).
- `games/catch/`: Catch. `index.html` loads `catch.js` (drawing, the thumb, pause, haptics; its tuning block `CONFIG` sits at the top; the drag follows the shared thumb travel), which runs `sim.js` (the fixed 120 Hz simulation: falling things, the boat, the nasty ones and the fish, the pace, the spawn timers and the variety; the input rules for taps, the 400 ms pause grace and the resume as a small state machine; the sprite masks; no DOM, no imports, so it also runs in Node; the session clock is passed in). The catches and nasties eaten since the opening drive the variety only; they are never shown or stored. Bricks keeps its own input code and its immediate pause.
- `games/putt/`: Putt. `index.html` loads `putt.js` (drawing, the pull-back gesture, haptics with the shared 40 ms limit, the level queue; its play values `CONFIG` sit at the top). `sim.js` is the fixed 120 Hz simulation (row U2: the screen less its safe-area insets is the course and its edges the walls; stubs as boxes, corner cuts and wedges as triangles; swept collisions in sub-steps of at most 1 px, constant deceleration, sand, water, the hole, the aim guide; no DOM, no imports). `gen.js` is the level generator and its solver (no DOM; its values `GEN`, with the PLAN §6c table and row U2's edge pieces, sit at the top; `lookOf` alternates sand and sea levels from a sand start, drawing only): a seed, a difficulty and the screen height always give the same level; `putt.js` runs `gen.js` as a module Web Worker to build the next level while one is played (in small slices on the page if a worker cannot start). Putt advances the shared session clock in memory while the ball rolls, while the thumb is down and for `CONFIG.idleS` after either.
- `games/stack/`: Stack. A tap anywhere but the side edges drops the sliding block; the game pauses only while the page is hidden. `index.html` loads `stack.js` (drawing, the tap, the overhang bits, haptics with the shared 40 ms limit; its play values `CONFIG` sit at the top), which runs `sim.js` (the fixed 120 Hz simulation: the sliding block, the drop and its cut, the tower, the camera, the missed block and the pace; no DOM, no imports). All visible time counts on the shared session clock.
- `games/glide/`: Glide (row A1, PLAN §6i), beach air hockey against a crab. `index.html` loads `glide.js` (drawing, the relative drag both ways on the shared thumb travel, pause on lift and the 250 ms resume, haptics with the shared 40 ms limit, the shared session clock; its play values `CONFIG` sit at the top), which runs `sim.js` (the table, the fixed 120 Hz simulation with swept collisions, the goals, the serve, the stall and pin rules, the pieces' masks and the table's colours from the token module passed in; no DOM, no imports) and `bot.js` (the crab: the reaction delay, the speed cap, the aim error and the silent rubber band; no DOM, no imports). Nothing is counted or stored.
- `manifest.webmanifest`, `sw.js`, `icons/` (drawn by `tools/make-icons.py` from the approved beach-sunset art; `icon-512.png` is the Play icon). The hub's cards open `games/<game>/index.html` by name (the Android app's local server answers a folder URL with the hub).
- `android-app/`: the Android app (row P3, PLAN §6f): a Capacitor shell with these files bundled (`tools/build-www.mjs` copies exactly `sw.js` FILES into `android-app/www`, not in git), the native haptics plugin and `MainActivity` (immersive, portrait, back) in `android/app/src/main/java/io/github/apcanario/rlx/`, the launcher icons in `android/app/src/main/res/`. The service worker is neither shipped nor registered in the app. Build, signing, install and release: `docs/PLAY.md`; CI: `.github/workflows/android.yml`.
- `privacy-policy.html`: the app's privacy policy, served by Pages at `/4rk4d3/privacy-policy.html`, not shipped in the app or the service worker. `docs/play/`: the store listing, Data safety and content rating answers, the icon, the feature graphic and the screenshots.
- `tools/`, `tests/`: helper scripts and tests. Nothing in them is needed to run the app. The games expose test hooks (`canvas.dataset.scene`, `window.__bricks`, `__catch`, `__putt`, `__stack`: snapshots are copies; Bricks and Catch also hand the tests their live state, to set up a scene); the games never read them.

All paths are relative, so the site works at a domain root or under a project subpath such as `/4rk4d3/`.

## Run locally

Serve the repo root with any static server and open it in Chrome:

    python3 -m http.server 8000
    # then open http://localhost:8000/

Use `localhost` (a secure context) so the service worker registers. Use Chrome DevTools device mode at 360 to 412 px wide to see the phone layout.

## Deploy

GitHub Pages serves the static files straight from the `main` branch, repo root. There is no build and no workflow.

1. Once: in the repo on GitHub, Settings, Pages, Source "Deploy from a branch", branch `main`, folder `/ (root)`. The site is then at `https://apcanario.github.io/4rk4d3/`. `.nojekyll` tells Pages to serve the files as they are.
2. Every deploy that changes a shipped file: run `tools/bump-sw-version.sh` (it bumps `VERSION` in `sw.js`), commit, push to `main`. If you added a shipped file, add it to `FILES` in `sw.js` too.

How updates reach the phone: `sw.js` serves every file cache-first from a cache named after `VERSION`, so the app opens offline. On each launch Chrome rechecks `sw.js` (registered with `updateViaCache: 'none'`). A changed `VERSION` installs the new worker, which caches the new files under the new name, takes over and deletes the old cache. The launch after that runs the new version.

Install: open the Pages URL in Chrome for Android, then menu, Add to home screen (or Install app). It opens fullscreen, in portrait.
